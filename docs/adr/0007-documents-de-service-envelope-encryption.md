# Documents de service are encrypted in the browser with a key the server keeps

A Dossier's Documents (diplômes, relevés bancaires, passeports) are the most sensitive files the platform holds. #79 asks that they be encrypted at rest yet readable by the consultant, so they can't use the Coffre-fort's zero-knowledge design (ADR 0001), where only the member holds the key. They also outgrow a server upload: a Vercel Function accepts about 4.5 MB per request, and a phone scan is often larger.

We decided on envelope encryption. For each file, the browser draws a fresh AES-256-GCM key and encrypts the file with Web Crypto. It then asks `/api/dossiers/upload` where to put it. That route answers only for that Dossier's Client or the consultant while the Dossier is open: it picks a fresh key under `dossiers/<dossierId>/` in the private R2 bucket (#87) and returns a short-lived presigned PUT address for it. The browser sends the ciphertext straight to that address, then calls `dossiers.documents.addVersion` with the object key and the file's key. The server checks that the object is in the Dossier's folder and exactly 16 bytes larger than the size announced (the GCM tag); a file that doesn't match is deleted. The server then stores the file's key encrypted with `DOSSIER_FILES_KEY` (the "wrapped key"); it never stores the plain key. `/api/dossiers/files/<versionId>` checks access again, unwraps the key, reads the object, decrypts it and serves it with `Cache-Control: private, no-store`. No tRPC procedure returns an object key's address or a file's key. Preuves de paiement follow the same path under `invoices/<invoiceId>/`.

The bucket is private: nothing in it can be read without the R2 API token, and even then only as ciphertext, useless without the database row and the master key. (The first version stored the files in Vercel Blob's public store; #87 moved every file to Cloudflare R2 once Blob's monthly limit blocked uploads.)

The browser chooses the file's key, so a Client could upload something that isn't encrypted properly. That only harms their own file. The server can't check what's inside, only that it's there and the right size.

`DOSSIER_FILES_KEY` must never change once files exist: rotating it means re-wrapping every key, which needs a script that doesn't exist yet. Losing it loses every Document de service.

We considered encrypting on the server. We rejected it: every upload would have to fit in one Function request. We also considered leaving files unencrypted in the private bucket. We rejected it because a leaked R2 token alone would then expose every passport.
